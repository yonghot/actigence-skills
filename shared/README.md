# shared/

여러 스킬이 함께 쓰는 원본 파일을 둔다. 스킬은 zip 으로 단독 업로드되어도 동작해야 하므로, 원본에서 파생한 사본을 각 스킬 폴더에 커밋한다. 사본은 직접 고치지 않는다.

## design-rules

- 원본: `shared/design-rules/design-rules.src.md` (gov 판 전체, 번호 1~14)
- 파생 사본(둘 다 커밋):
  - `plugins/infographic/skills/infographic/references/design-rules.md` (variant `base`)
  - `plugins/gov-doc-infographic/skills/gov-doc-infographic/references/design-rules.md` (variant `gov`)

### 파생 규칙

원본에는 단독 한 줄짜리 마커 줄이 있다. 마커 줄 자체는 항상 출력에서 빠진다.

| 마커 쌍 | base 사본 | gov 사본 |
|---|---|---|
| `<!-- gov-only -->` ... `<!-- /gov-only -->` | 블록 삭제 | 블록 유지 |
| `<!-- base-only -->` ... `<!-- /base-only -->` | 블록 유지 | 블록 삭제 |

마커 밖의 줄은 두 사본에 그대로 들어간다. 파생 후에는 다음을 적용한다.

1. 줄바꿈을 LF 로 통일한다.
2. 둘째 줄에 `<!-- generated by shared/build-design-rules.mjs from shared/design-rules/design-rules.src.md (variant: <base|gov>); edit the source, not this copy -->` 를 삽입한다.
3. 빈 줄 2개 이상 연속을 빈 줄 1개로 줄인다.
4. 파일 끝은 개행 1개로 맞춘다.

결과적으로 gov 사본은 base 사본의 상위집합이며, 개요 셀 관련 내용(목차 14번, 2·4·5·11·13번의 개요 부분, 14번 전체)은 gov 사본에만 있다.

### 명령

```
node shared/build-design-rules.mjs          # 원본에서 두 사본을 다시 생성
node shared/build-design-rules.mjs --check   # 사본이 원본 파생 결과와 같은지 확인 (다르면 종료 코드 1)
```

검증기(validator)와 CI 는 `--check` 를 호출하면 된다. 같은 결과를 직접 확인하려면 위 규칙을 구현해 두 사본과 바이트 단위로 비교한다. 외부 의존성은 없고 Node 18 이상이면 된다.

### 수정 절차

1. `design-rules.src.md` 만 수정한다.
2. `node shared/build-design-rules.mjs` 를 실행한다.
3. 두 사본과 원본을 함께 커밋한다.
4. 규칙을 바꿨으면 두 스킬의 `docs/changelog/` 에 기록한다.
