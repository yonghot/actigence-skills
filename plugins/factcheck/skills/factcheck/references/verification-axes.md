# 7축 검증 프레임워크 상세 정의

이 파일은 각 축의 검증 대상, 문서 유형별 초점, 검증 방법을 상세히 정의한다.
스킬 실행 시 반드시 이 파일을 읽은 후 검증을 시작한다.

---

## 축1. 사실 정확성 (Factual Accuracy)

**검증 대상:**
- 수치, 통계, 날짜, 고유명사, 인용문이 실제 출처와 일치하는지
- 인물의 직함·소속·이력이 현재 기준으로 정확한지
- 기관명·법인명·제도명의 정확한 표기

**TYPE_A 추가 초점:**
- 시장 규모(TAM/SAM/SOM), 성장률(CAGR), 점유율의 출처·시점·산출 근거

**TYPE_B 추가 초점:**
- 인용된 연구·보고서의 저자, 발행 기관, 발행 연도, 페이지/섹션 정확성
- 통계 수치가 원출처의 맥락에서 벗어나 인용되지 않았는지 (맥락 왜곡)
- 1차 자료(원논문, 정부 통계)와 2차 자료(뉴스, 블로그) 구분 여부

**검증 방법:**
- [필수] 핵심 수치 3개 이상을 웹 검색으로 원출처와 대조
- [권장] 1차 출처(정부 통계, 기관 공식 발표, 원논문)를 우선 참조
- [권장] 데이터 시점이 2년 이상 경과한 경우 최신 데이터 존재 여부 확인

---

## 축2. 논리적 정합성 (Logical Consistency)

**검증 대상:**
- 문서 내 섹션 간 모순 (A 섹션의 주장 vs B 섹션의 주장)
- 원인-결과 관계의 논리적 타당성
- 전제와 결론 사이의 비약 여부
- 삼단논법의 숨은 전제 존재 여부

**TYPE_B 추가 초점:**
- 분석 프레임워크의 내적 일관성 (정의한 분석 틀을 끝까지 일관되게 적용했는지)
- 증거의 가중치: 약한 증거로 강한 결론을 도출하지 않았는지
- 반론·한계점의 공정한 다룸 여부

**검증 방법:**
- [필수] 핵심 논증 구조를 "전제 → 추론 → 결론" 형태로 분해하여 각 연결의 타당성 점검
- [권장] "A이므로 B이다" 형태의 주장에서 반례 존재 여부 확인

---

## 축3. 가정 검증 (Assumption Audit)

**검증 대상:**
- 명시적 가정 (문서에 직접 서술된 전제)
- 암묵적 가정 (서술되지 않았으나 논증 성립에 필요한 전제)
- 미래 예측 표현에 숨은 가정 ("~할 것이다", "~로 예상된다", "~이면 가능하다")

**TYPE_B 추가 초점:**
- 분석 범위 설정(scope)에 내재된 가정: "이 리포트는 X만 다룬다"가 결론을 편향시키지 않는지
- 인과 모델의 숨은 변수: 고려하지 않은 교란 변수(confounding variable)

**검증 방법:**
- [필수] 모든 가정을 추출하여 각각 [합리적 / 낙관적 / 비현실적]으로 판정
- [필수] 판정 근거를 1문장 이상 기술. 근거 없는 판정은 금지
- [권장] 가정이 무너질 경우의 영향도(상/중/하)를 함께 평가

---

## 축4. 수치·데이터 무결성 (Numerical & Data Integrity)

### TYPE_A 초점 — 재무 검증
- 산술 정확성 (합계, 비율, 증감률, 단위 환산)
- 재무 추정의 전제 조건 명시 여부와 합리성
- 매출·비용·이익 구조의 내적 일관성 (수익 모델 ↔ 재무제표 정합)
- 업계 벤치마크 대비 이상치(outlier) 탐지
- [필수] 매출 추정 시 "단가 × 고객 수 × 빈도"의 각 변수가 근거를 갖는지 확인
- [권장] 영업이익률, CAC, LTV 등 핵심 지표를 업계 평균과 비교
- [선택] BEP(손익분기점) 도달 시점의 현실성 평가

### TYPE_B 초점 — 데이터 무결성
- 제시된 수치·표·그래프의 산술 정확성
- 데이터 출처의 신뢰도 등급 (정부 통계 > 리서치 기관 > 뉴스 > 블로그·커뮤니티)
- 표본 크기·조사 방법론의 적절성 (서베이 n수, 조사 기간, 모집단 대표성)
- 동일 지표에 대해 문서 내 서로 다른 위치에서 다른 수치를 사용하지 않았는지
- [필수] 핵심 데이터의 출처 신뢰도를 [높음/보통/낮음/불명]으로 태깅
- [권장] 리서치 기관 보고서 인용 시 해당 보고서의 조사 방법론 한계 확인

### TYPE_C
TYPE_A와 TYPE_B를 문서 내용에 맞게 선택 적용

### 공통
- [필수] 문서 내 모든 산술 연산을 재계산하여 오류 탐지

---

## 축5. 맥락 검증 (Contextual Validation)

### TYPE_A 초점 — 시장·경쟁 검증
- 시장 정의의 적절성 (너무 넓거나 좁지 않은지)
- TAM/SAM/SOM 산출 로직과 출처
- 경쟁사 분석의 현재성 (폐업·피벗·신규 진입자 반영)
- 차별화 주장의 실증적 근거
- [필수] 시장 규모 수치를 웹 검색으로 교차 검증. 출처 간 편차가 크면 범위로 제시
- [권장] 경쟁사 목록에서 누락된 주요 플레이어가 있는지 검색으로 확인
- [권장] "국내 최초", "유일한 솔루션" 등의 차별화 주장을 반증하는 사례 탐색

### TYPE_B 초점 — 출처 품질·방법론 검증
- 출처 다양성: 단일 출처 또는 단일 관점에 과도하게 의존하지 않았는지
- 출처 최신성: 핵심 논거를 뒷받침하는 출처가 적절한 시점의 것인지
- 출처 편향성: 이해관계가 있는 기관(업계 후원 리서치 등)의 자료를 무비판적으로 인용하지 않았는지
- 방법론 투명성: 분석 방법(정성/정량, 비교 기준, 사례 선정 기준)이 명시되고 재현 가능한지
- 누락된 관점: 주요 반론, 대안적 해석, 소수 의견이 공정하게 다뤄졌는지
- [필수] 핵심 논거를 뒷받침하는 출처가 3개 미만이면 플래그
- [권장] 이해충돌 가능성이 있는 출처를 식별하고 명시

### TYPE_C
문서 맥락에 맞게 위 두 초점을 혼합 적용

---

## 축6. 법률·규제 검증 (Legal & Regulatory Check)

**검증 대상:**
- 인용된 법령·규제의 정확한 명칭과 조항 번호
- 최신 법률 개정 사항 반영 여부
- 인허가·자격 요건·신고 의무의 정확성
- 개인정보보호, 의료기기, 금융 등 특수 규제 영역 해당 여부

**TYPE_B 추가 초점:**
- 정책 분석 시 해당 정책의 현행 시행 상태 (시행 중 / 개정 예고 / 폐지)
- 해외 사례 인용 시 해당국 법률 맥락의 정확성

**검증 방법:**
- [필수] 법령명이 인용된 경우 국가법령정보센터(law.go.kr) 기준으로 현행 여부 확인
- [권장] 규제 샌드박스, 특례 적용 주장이 있는 경우 실제 사례를 검색으로 확인
- [선택] 향후 입법 예고 중인 관련 법안이 있는지 탐색

법률·규제 내용이 없는 문서의 경우 이 축은 "해당 없음"으로 처리한다.

---

## 축7. 표현·과장 검증 (Rhetoric & Overclaim Detection)

**검증 대상:**
- 절대 표현: "최초", "유일", "혁신적", "압도적", "획기적"
- 선택적 데이터 인용으로 인한 왜곡 (체리피킹)
- 상관관계를 인과관계로 오인한 표현
- 모호한 권위 인용: "전문가에 따르면", "연구에 의하면" (구체적 출처 없이)

**TYPE_B 추가 초점:**
- 확증 편향: 결론을 지지하는 증거만 선별하고 반증을 무시하지 않았는지
- 일반화 오류: 제한된 사례를 전체로 확대 적용하지 않았는지
- 정밀도 허위: 불확실한 추정치를 지나치게 구체적 숫자(소수점 이하)로 표현하지 않았는지

**검증 방법:**
- [필수] 절대 표현이 있으면 반증 사례를 1건 이상 탐색. 반증 불가 시에만 통과
- [권장] "~에 따르면" 형태의 인용에서 구체적 출처(저자, 기관, 연도)가 명시되었는지 확인

---

## 교차 축 모순 탐지 체크리스트

7축 검증 완료 후, 아래 교차 패턴을 점검한다:

- 축3 낙관적 가정 → 축4 재무/데이터 추정에 직접 영향
- 축1 사실 오류 → 축2 논증 구조 무너뜨림
- 축5 출처 편향 → 축7 확증 편향과 연결
- 축6 법령 오류 → 축3 가정 전제 자체가 무효화
- 축4 산술 오류 → 축1 수치 기반 사실 주장 무효화
