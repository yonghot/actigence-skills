# SEO · AEO · GEO 적용

## 발동 조건 (자동 발동 시 먼저 확인)

사용자 메시지에 `SEO` 라는 단어가 그대로 있을 때만 진행한다.
없으면 즉시 중단하고 사용자에게 알린다. 단어가 있어도 개념을 묻는 질문이거나 작업 폴더의 프로젝트에서 수행해 달라는 요청이 아니면 진행하지 않고 답만 한다. `/seo-aeo-geo` 명시 호출은 조건을 만족한 것으로 본다.

대상은 **이미 운영 중인 사이트**다. 빈 폴더에서 새로 시작하는 경우라면 `oneshot-prototyping` 쪽이며, 그 스킬은 SEO 를 범위 밖으로 두고 이 스킬을 쓰라고 안내한다.

## 실행 규약

1. `references/prompt.md` 전문을 **먼저 끝까지 읽는다.** 요약·발췌로 대체하지 않는다.
2. 그 문서가 이 작업의 운영 지침 정본이다. 사용자의 요청문과 저장소가 입력이다.
3. 카드가 정의한 8 게이트·F 시리즈 검사·종료 신호를 그대로 따른다. 이 SKILL.md 는 라우팅만 하고 규칙을 덮어쓰지 않는다.

## 이 카드의 특성

- **색인 신호가 유일한 비가역 변경** — `.proposed` 사본으로 되돌릴 수 없다. `noindex`·off-page canonical·content 경로 `Disallow`·기존 URL 이탈 리다이렉트는 INDEX_SAFETY 를 통과해야만 기록된다. "search/filter/preview" 같은 패턴 목록은 후보일 뿐 권한이 아니다 — `/search` 가 주력 유입 페이지인 사이트가 흔하다.
- **베이스라인 먼저** — 변경 전에 `00-baseline.md` 를 쓴다. 이게 없으면 작업량은 보고해도 효과는 보고할 수 없다.
- **측정이지 추론이 아니다** — 크롤 도달성(F-7)과 Core Web Vitals(F-8)는 실제 도구를 돌려 before/after 를 비교한다. 도구가 없으면 `[SKIPPED]` + 사용자가 돌릴 명령을 남기지, 통과로 적지 않는다.
- **기존 파일 무편집** — 새 파일 · `.proposed` 사본 · 마이그레이션 문서만. 예외는 빈 파일이거나 사소한 default export 뿐.
- **비차단** — F-2/F-3/F-6/F-7/F-8 위반은 fix loop 로 수렴하고 롤백을 부르지 않는다. 롤백 조건은 빌드·타입체크·핵심 라우트 5xx 셋뿐.
- **종료 신호 4종** — `SEO_AEO_GEO_APPLIED_AND_VERIFIED` / `ROLLED_BACK` / `CONTEXT_HANDOFF` / `NEEDS_HUMAN_REVIEW` 중 하나가 기록될 때까지 끝내지 않는다.
- 산출물은 격리 브랜치 + PR 이며, PR 본문이 최종 보고서다. DB 마이그레이션은 생성만 하고 실행하지 않는다.

## 출처

ACTIGENCE 프롬프트 카드 `setup-seo-aeo-geo` v1.14 와 동기화되어 있다. `references/prompt.md` 는 카드 본문과 byte-exact 사본이므로 이 저장소에서 편집하지 않는다.
프롬프트가 언급하는 모델 이름은 등급(경량·표준·최상위)을 뜻한다. 사용 중인 환경의 현재 모델 계열에 맞춰 대응시킨다. 이 안내는 카드 규칙을 바꾸지 않는 해설이다.
