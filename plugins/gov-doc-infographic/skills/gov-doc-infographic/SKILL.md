# 정부지원사업 제출 문서 인포그래픽 자동 생성 스킬

정부·공공기관 지원사업 제출용 사업계획서, 연구개발계획서 등의
핵심 내용을 도식화한 고품질 인포그래픽 HTML을 생성한다.
정부지원사업이 아닌 일반 문서는 infographic 스킬이 맡는다.

**두 가지 산출물**을 생성한다:
1. **전체 인포그래픽** (`infographics.html`) — 문서 전체를 15~20개 섹션으로 도식화
2. **개요 셀 인포그래픽** (`infographics_overview.html`) — 문서 초반 개요 테이블의 각 셀에 삽입할 소형 인포그래픽

## 사용 전 필수 행동

이 SKILL.md 와 같은 폴더의 `references/design-rules.md` 를 읽어라.
스킬의 참조 파일은 이 SKILL.md 가 있는 폴더 기준 상대 경로로 읽는다.

## 핵심 원칙

1. **수치 정확성**: 원문 그대로. 반올림·추정·창작 금지.
2. **잘림 금지**: max-height+overflow:hidden 금지. height:auto.
3. **순서 유지**: 원문 목차 순서.
4. **개인정보 마스킹**: 이름→성OO, 학교→OO대.
5. **배경 = 흰색**: #FFFFFF 또는 transparent만. 인쇄 잉크 0.
6. **텍스트 = 검정**: #000000. 출처와 캡처 라벨(.cap-label, 인쇄 시 숨김)만 #666666.
7. **테마컬러 1개만**: 문서 주제에 어울리는 뮤트 톤 1색. 보라색 금지.
8. **Pretendard 단일**(오프라인 폴백 스택 제외): 본문 최소 16px (개요 셀은 최소 13px까지 허용 — 공간 제약).
9. **이모지 완전 금지**.
10. **AI스러운 디자인 금지**.

## 워크플로우

### STEP 1: 문서 읽기 + 분석

- 파일 확보 (파일 접근이 가능한 에이전트 환경: 경로 탐색 / 채팅: 첨부)
- 정부지원사업 제출용 문서인지 확인. 아니면 infographic 스킬을 쓰도록 안내
- 테마컬러 1색 선택 (design-rules.md 가이드)
- 실제 목차 파악 + 순서번호 기록
- **개요 테이블 감지** (아래 OVERVIEW_DETECTION 참조)
- 도식화 대상 선별 + 데이터 추출 + 마스킹

### STEP 2: 섹션 설계

**전체 인포그래픽**: 15~20개, 원문 순서, 패턴 다양화. 원문이 짧아 의미 있는 섹션이 15개에 못 미치면 억지로 채우지 않고 만든 섹션 수와 이유를 밝힌다.
**개요 셀 인포그래픽**: 감지된 개요 테이블의 각 셀별 소형 인포그래픽 설계

### STEP 3: HTML 생성

두 개의 HTML 파일을 작업 폴더에 생성:
- `infographics.html` — 전체 인포그래픽
- `infographics_overview.html` — 개요 셀 인포그래픽

### STEP 4: 검증 (design-rules.md 체크리스트)

체크리스트를 읽어서 판단하지 말고 가능한 방법으로 실측한다.
1. 헤드리스 브라우저(Playwright, Chrome/Edge `--headless`)가 있으면 전체는 900px, 개요는 700px 폭으로 렌더해 잘림·가로 스크롤·겹침이 없고 섹션 높이가 auto 인지 본다.
2. 브라우저가 없으면 HTML 을 텍스트로 검사한다: 이모지 문자, 보라색 계열 hex, 본문 font-size 하한(전체 16px, 개요 13px) 미만, `max-height`/`overflow:hidden`, #000·#666 외 텍스트 색.
3. 두 경우 모두 HTML 의 숫자 문자열을 원문과 대조한다(원문에 없는 수치 0건).
검사에서 `.cap-label` 은 제외한다(design-rules.md 11번). 산출 보고에 1·2 중 무엇을 실행했는지, 실행하지 못한 검사가 무엇인지 밝힌다.

### STEP 5: 출력
산출 파일은 작업 폴더에 저장한다(claude.ai 에서는 /mnt/user-data/outputs/). present_files 도구가 있으면 그것으로 전달한다. 두 파일 모두 저장한다.
파일을 쓸 수 없는 채팅 환경: 두 HTML을 각각 코드블록으로 출력 (전체 먼저, 개요 다음)

## 실패 모드

- **스캔 PDF·이미지뿐인 원문**: 텍스트를 읽을 수 없으면 추정하지 말고 텍스트 파일이나 OCR 결과를 요청한다.
- **여러 사업이 섞인 문서**: 사업별로 목차를 나누고, 어느 사업 기준으로 만들었는지 밝힌다.
- **개요 테이블 없음**: 개요 셀 파일은 만들지 않고 전체 인포그래픽만 생성한다.
- **오프라인**: Pretendard CDN 을 못 불러오면 design-rules.md 의 폴백 스택으로 렌더되므로 글꼴이 다를 수 있다고 밝힌다.

## OVERVIEW_DETECTION — 개요 테이블 감지 및 셀 인포그래픽 생성

### 개요 테이블이란?

정부지원사업 제출 문서의 초반부(보통 1~3페이지)에 있는 표 형식의 요약 페이지.
문서 유형에 따라 다양한 형태가 있다:

**사업계획서 (창업지원사업)**
- "일반현황" 또는 "창업 아이템 개요(요약)" 페이지
- 셀 예시: 아이템명/범주, 아이템 개요, 문제인식 요약, 실현가능성 요약, 성장전략 요약, 팀 구성 요약, 이미지

**연구개발계획서 (R&D)**
- "과제 개요" 페이지
- 셀 예시: 과제명, 개발 목표, 개발 방법, 연구팀 구성, 기대효과

**기타 계획서**
- 유사한 표 형식 개요가 있을 수 있음

### 감지 방법

문서를 읽을 때 아래 패턴을 찾아라:
1. 문서 초반(1~3페이지)에 있는 표(table) 구조
2. 좌측 열이 항목명(과제명, 개발 목표, 아이템 개요 등), 우측 열이 내용인 구조
3. 또는 "일반현황", "과제 개요", "아이템 개요", "사업 개요" 등의 제목 아래 표

감지되면 각 셀의 항목명과 내용을 추출하라.
감지되지 않으면 개요 셀 인포그래픽은 생성하지 않고, 전체 인포그래픽만 생성하라.

### 셀 인포그래픽 설계 규칙

각 셀용 인포그래픽은 해당 셀에 이미지로 삽입할 것이므로, 표 셀 크기에 맞아야 한다.

**사이즈**
- 가로: 700px (표 우측 셀 너비에 맞춤)
- 세로: 셀 내용량에 따라 자동 (height:auto), 대략 150~400px
- 패딩: 12~16px

**디자인 — 셀에 삽입되므로 더 컴팩트하게**
- 배경: transparent (셀 배경에 자연스럽게 녹아들도록)
- 테두리: 없음 (셀 자체에 테두리가 있으므로)
- 폰트: Pretendard, 최소 13px까지 허용 (셀 공간이 작으므로 전체 인포그래픽보다 작게 허용)
- 핵심 숫자: 36~48px weight 800
- 소제목: 16~20px weight 700
- 본문: 13~15px weight 500
- 테마컬러: 전체 인포그래픽과 동일한 1색

**셀별 도식화 방법 — 항목명에 따라 최적 시각화 선택**

| 항목명 패턴 | 도식화 방법 |
|------------|-----------|
| 과제명 / 아이템명 | 큰 텍스트(24~30px weight 800) + 한줄 설명. 도식보다 타이포그래피로 임팩트. |
| 개발 목표 / 아이템 개요 | 핵심 키워드 3~5개를 가로 나열 + 각각 아래에 1줄 설명. 또는 좌측 핵심숫자 + 우측 설명. |
| 개발 방법 / 실현가능성 | 3~5단계 가로 플로우(스텝 화살표). 각 스텝에 키워드+1줄. |
| 연구팀 구성 / 팀 구성 | 가로 카드(이니셜+성OO+직책+핵심역량). 3~5명 1줄. |
| 기대효과 / 성과 목표 | 핵심 수치 3~4개를 가로 나열 (숫자 36~48px + 라벨). |
| 문제인식 요약 | 핵심 문제 2~3개를 가로 카드 (아이콘+키워드+1줄). |
| 성장전략 요약 | 핵심 전략 2~3개를 가로 카드 또는 가로 타임라인. |
| 사업비 / 예산 | 총액(큰 숫자) + 가로 비율바. |
| 이미지 / 참고 사진 | 이 셀은 실제 서비스 화면이나 제품 사진을 넣는 칸이므로 인포그래픽 대상 아님. 건너뛰기. |

**개요 HTML 구조**

infographics_overview.html에 각 셀을 개별 section으로 나열.
각 section에 캡처 가이드 라벨: "#번호 -- {항목명} [개요 셀]" (`.cap-label`: 12px #666, 인쇄 시 숨김 — design-rules.md 11번)
사용자는 각 section을 개별 스크린샷 → 해당 표 셀에 이미지로 삽입.

```html
<section id="cell-1" style="width:700px; height:auto; background:transparent; padding:14px;">
  <div class="cap-label">#1 -- 개발 목표 [개요 셀]</div>
</section>

<section id="cell-2" style="width:700px; height:auto; background:transparent; padding:14px;">
  <div class="cap-label">#2 -- 개발 방법 [개요 셀]</div>
</section>
```

### 과제명/아이템명 셀 처리

과제명이나 아이템명 셀은 단순 텍스트만 들어가는 경우가 많아 도식화 효과가 낮다.
이 셀은 인포그래픽을 만들되, 큰 타이포그래피(24~30px weight 800)로 과제명을 표시하고
아래에 한줄 설명(범주, 핵심 키워드 등)을 붙이는 정도로 간결하게 처리하라.
내용이 충분하지 않으면 이 셀은 건너뛰어도 된다.

### "이미지" 셀 처리

"이미지", "참고 사진", "서비스 화면" 등의 항목은 실제 스크린샷이나 제품 사진을 넣는 칸이다.
이 셀에는 인포그래픽을 생성하지 않는다. 건너뛰기.
