# 디버깅

## 발동 조건 (자동 발동 시 먼저 확인)

사용자 메시지에 `디버깅` (영어로는 `debugging`) 이라는 단어가 그대로 있을 때만 진행한다.
없으면 즉시 중단하고 사용자에게 알린다. 단어가 있어도 개념을 묻는 질문이거나 작업 폴더의 프로젝트에서 수행해 달라는 요청이 아니면 진행하지 않고 답만 한다. `/debug-rootcause` 명시 호출은 조건을 만족한 것으로 본다.

## 실행 규약

1. `references/prompt.md` 전문을 **먼저 끝까지 읽는다.** 요약·발췌로 대체하지 않는다.
2. 그 문서가 이 작업의 운영 지침 정본이다. 사용자가 보고한 증상(로그·스택트레이스·스크린샷 포함)이 입력이다.
3. 카드가 정의한 Iron Law·게이트·출력 계약을 그대로 따른다. 이 SKILL.md 는 라우팅만 하고 규칙을 덮어쓰지 않는다.
4. 스킬의 참조 파일은 이 SKILL.md 가 있는 폴더 기준 상대 경로로 읽는다.

## 자율 실행 주의와 사용자 제외 조항

이 스킬의 지침은 확인 질문 없이 끝까지 진행하며, 수정이 배포 가능한 산출물을 바꾸면 운영 배포와 공유·운영 DB 변경까지 수행한다. 실행 전에 이 점을 알고 호출한다.

사용자가 "배포하지 마"라고 하거나 "공유·운영 DB 는 건드리지 마"라고 말했으면 해당 단계(배포, 공유·운영 DB 변경 적용)는 그 사유와 함께 `[SKIPPED]` 로 표시하고 나머지는 그대로 진행한다. 사용자의 명시적 제외는 이 단계들에 한해 카드의 '무조건·묻지 않음' 표현보다 우선한다. 이 조항은 단계를 건너뛰기만 하며 확인 질문을 새로 추가하지 않는다.

## 이 카드의 특성

- **근거 우선** — 근본 원인이 구체적 증거로 확인되기 전에는 코드를 수정하지 않는다(Iron Law). 재현 시나리오 확보가 최우선이며, 재현이 계속 실패하면 약 3회 시도 뒤 가정과 관찰 증거를 기록하고 가장 유력한 가설로 진행하되 추측 수정은 여전히 금지다. 증상만 보고 고치는 것은 위반이다.
- **가설 3개 병렬** — 단일 가설로 수렴하지 않는다.
- **회귀 테스트 필수** — 수정만으로 끝내지 않고 같은 결함을 다시 잡는 테스트를 남긴다.
- **재발 방지 3종** — 회귀 테스트는 CI만 지킨다. 운영 감지 신호 · 누락 제약 복원 · 워크어라운드 제거 트리거까지 닫고 인시던트 로그에 남긴다.
- **웹앱 가정 금지** — CLI·라이브러리·확장·데스크톱·모바일·api-service·데이터 파이프라인에 동일 워크플로가 적용된다. UI 리뷰·브라우저 도구 규칙은 그 표면이 존재할 때만.

## 출처

ACTIGENCE 프롬프트 카드 `dev-merged-5` v1.11 에 **Recurrence 확장**(재발 방지 3종: Detection · Constraint restoration · Workaround retirement)을 더한 상위 사본이다. 카드 v1.11 이 가진 내용은 모두 포함하고 위 확장만 추가되어 있다. `references/prompt.md` 는 이 저장소에서 편집하지 않는다.
프롬프트가 언급하는 모델 이름(Haiku·Sonnet·Opus 등)은 등급(경량·표준·최상위)을 뜻한다. 사용 중인 환경의 현재 모델 계열에 맞춰 대응시킨다. 이 안내는 카드 규칙을 바꾸지 않는 해설이다.
