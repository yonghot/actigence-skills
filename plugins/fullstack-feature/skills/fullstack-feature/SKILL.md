# 풀스택 기능 구현

## 발동 조건 (자동 발동 시 먼저 확인)

사용자 메시지에 `풀스택` 과 `구현` (영어로는 `fullstack` 과 `implement`) 이라는 **두 단어가 모두** 있을 때만 진행한다.
한쪽만 있으면 즉시 중단하고 사용자에게 알린다. 두 단어가 있어도 개념 질문이거나 작업 폴더의 프로젝트에서 수행해 달라는 요청이 아니면 진행하지 않고 답만 한다. `/fullstack-feature` 명시 호출은 조건을 만족한 것으로 본다.

## 실행 규약

1. `references/prompt.md` 전문을 **먼저 끝까지 읽는다.** 요약·발췌로 대체하지 않는다.
2. 그 문서가 이 작업의 운영 지침 정본이다. 사용자의 기능 요청문(또는 기능 명세·PRD)이 입력이다.
3. 카드가 정의한 게이트·수용 기준·출력 계약을 그대로 따른다. 이 SKILL.md 는 라우팅만 하고 규칙을 덮어쓰지 않는다.
4. 스킬의 참조 파일은 이 SKILL.md 가 있는 폴더 기준 상대 경로로 읽는다.

## 자율 실행 주의와 사용자 제외 조항

이 스킬의 지침은 확인 질문 없이 끝까지 진행하며, 변경이 배포 가능한 산출물이면 운영 배포와 공유·운영 DB 마이그레이션 적용까지 수행한다. 실행 전에 이 점을 알고 호출한다.

사용자가 "배포하지 마"라고 하거나 "공유·운영 DB 는 건드리지 마"라고 말했으면 해당 단계(배포, 공유·운영 DB 마이그레이션 적용)는 그 사유와 함께 `[SKIPPED]` 로 표시하고 나머지는 그대로 진행한다. 사용자의 명시적 제외는 이 단계들에 한해 카드의 '무조건·묻지 않음' 표현보다 우선한다. 이 조항은 단계를 건너뛰기만 하며 확인 질문을 새로 추가하지 않는다.

## 이 카드의 특성

- **기능 1개 단위** — 여러 기능을 한 번에 요청받았으면 기능별로 나눠 호출한다.
- **계층은 코드베이스에서 도출** — "DB + API + 프론트"는 흔한 경우일 뿐 요구사항이 아니다. 이 저장소가 실제로 가진 계층에만 규칙을 적용한다.
- **웹앱 가정 금지** — 매니페스트·락파일·CI 설정에서 산출물 유형을 먼저 확정한다.

## 출처

ACTIGENCE 프롬프트 카드 `dev-merged-4` v1.12 와 동기화되어 있다. `references/prompt.md` 는 카드 본문과 byte-exact 사본이므로 이 저장소에서 편집하지 않는다.
프롬프트가 언급하는 모델 이름(Haiku·Sonnet·Opus 등)은 등급(경량·표준·최상위)을 뜻한다. 사용 중인 환경의 현재 모델 계열에 맞춰 대응시킨다. 이 안내는 카드 규칙을 바꾸지 않는 해설이다.
