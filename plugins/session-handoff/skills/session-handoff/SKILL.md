# Session Handoff

이 스킬은 현재 세션의 작업 맥락을 다음 세션이 "충분히" 이어받을 수 있는 핸드오프 md 파일로 생성한다. "충분히"의 기준은 다음 세션의 Claude가 이전 세션의 의사결정을 재탐색하지 않고 동일한 품질로 작업을 즉시 재개할 수 있는 수준이다.

## 언제 사용하는가

핸드오프 문서는 "살짝 변형된 작업" 유형에 가치가 있다.

- **완전히 연속적 작업**: 같은 세션에서 계속 진행 (핸드오프 불필요)
- **완전히 독립적 작업**: 새 세션에서 빈 상태로 시작 (핸드오프 불필요)
- **살짝 변형된 작업**: 이전 세션의 산출물·맥락·제약은 계승하되, 사고 경로와 누적된 대화 노이즈는 끊어낸다 ← **이 스킬의 대상**

자동 컴팩션은 "모든 것을 섞어서 압축"하기 때문에 "이번에 버리고 싶은 것"까지 따라온다. 수동 핸드오프의 핵심 가치는 **명시적 스코프 선언**과 **버릴 것의 명시화**에 있다.

## 핵심 원칙

<CRITICAL_CONSTRAINTS>
[MUST] 확정된 산출물(PRD, 코드, 보고서, 프롬프트, 스펙 등)은 원문 그대로 포함하라. 요약·축약·재구성을 수행하지 마라.

[MUST] "다음 세션에서 하지 말 것(OUT_OF_SCOPE)"을 명시적·구체적으로 선언하라. 암묵지로 남기지 마라. 이것이 자동 컴팩션으로는 절대 만들 수 없는 수동 핸드오프의 핵심 가치다.

[MUST] 각 확정된 의사결정에 대해 {결정 내용, 근거, 번복 금지 여부}를 쌍으로 기록하라. 결과만 기록하면 다음 세션에서 같은 논의가 재개된다.

[MUST] 시행착오, 폐기된 접근, 중간 버전, 해결 완료된 디버깅 기록을 제외하라. 단, 다시 유혹될 위험이 있는 폐기 항목은 "경계 사항" 섹션에 보존하라.

[MUST] 기존 PROGRESS.md가 있으면 그 경로를 메타 섹션에 기록하고, 다음 세션 첫 지시문에서도 참조하도록 안내하라. 핸드오프 문서는 PROGRESS.md를 대체하지 않고 보완한다.

[MUST] 다음 세션 첫 지시문에는 "OUT_OF_SCOPE 섹션을 먼저 읽고 그 범위를 절대 건드리지 않겠다는 확인"을 작업 개시 전 수행하도록 강제하는 문구를 반드시 포함하라.

[MUST] 산출물은 단일 .md 파일이며, 한글로 작성하라. 프로젝트별 히스토리가 누적되도록 경로 규칙을 따르라.

[MUST] 비밀값과 개인정보를 핸드오프에 옮기지 마라. 토큰·API 키·비밀번호·.env 값·개인 식별정보는 원문 보존 대상이 아니다. 값 대신 `<API_KEY: .env 의 SERVICE_KEY>` 처럼 위치만 가리키는 자리표시자를 쓴다. 핸드오프 폴더(`.claude/handoffs/`)는 저장소에 커밋되지 않도록 `.gitignore` 등록을 사용자에게 권한다.

[MUST] 원문 보존에는 크기 밸브가 있다. 산출물 하나가 약 300줄 또는 15KB를 넘으면 본문에 통째로 넣지 말고 파일 경로·크기·핵심 발췌(구조 목차, 확정된 핵심 구간)만 기록한다. 이 경우 원문이 있는 경로를 메타 섹션 "관련 파일 경로"에 반드시 적는다.
</CRITICAL_CONSTRAINTS>

## 내부 에이전트 구조

복잡한 세션에서는 다음 내부 분업으로 작업하라. 단일 Claude 세션에서는 순차·병렬로 역할 전환하며 수행한다.

### ORCHESTRATOR
사용자와의 짧은 스코프 인터뷰를 먼저 수행한 뒤, 세 개의 서브에이전트를 순차·병렬로 실행하고, 결과를 통합하여 핸드오프 md 파일을 최종 출력한다. 출력 직전 자기검증을 수행한다.

### SUB_AGENT: ScopeDefiner
- **입력**: 현재 세션의 최근 대화 + 사용자 답변 + 기존 PROGRESS.md (있는 경우)
- **수행**: 사용자에게 1-3개 질문으로 CHANGE(이어갈 것) / KEEP(유지할 것) / OUT_OF_SCOPE(건드리지 말 것)를 확정. PROGRESS.md가 있으면 그 내용을 참조하여 중복을 피하라.
- **완료 기준**: 세 항목이 모두 추상어가 아닌 구체적 대상·조건으로 정의됨

### SUB_AGENT: ArtifactExtractor
- **입력**: 현재 세션 전체
- **수행**: 최종 확정된 산출물(PRD, 코드, 보고서, 프롬프트, 결정된 스펙 등)을 원문 그대로 식별·수집. 중간 버전·초안은 제외.
- **완료 기준**: 모든 최종 산출물이 원문 형태로 누락 없이 수집됨

### SUB_AGENT: DecisionMiner
- **입력**: 현재 세션 전체
- **수행**: (1) 확정된 의사결정 + 근거, (2) 가드레일 제약조건, (3) 사용한 외부 레퍼런스, (4) 미결 질문/보류 사항, (5) 재유혹 위험이 있는 폐기 항목을 추출
- **완료 기준**: 각 의사결정에 "무엇을 결정했는가"와 "왜 그렇게 결정했는가"가 쌍으로 기록됨

### 파일 경로 규칙 (환경별 분기)

- **Claude Code 환경** (프로젝트 루트 접근 가능): `.claude/handoffs/{project-slug}/handoff-{YYYYMMDD-HHMM}.md`
- **웹/앱 환경** (claude.ai 등 단일 outputs 폴더): `/mnt/user-data/outputs/handoffs/{project-slug}/handoff-{YYYYMMDD-HHMM}.md`
- **경로 생성이 불가능한 환경**: `/mnt/user-data/outputs/handoff-{project-slug}-{YYYYMMDD-HHMM}.md` (평탄화)

웹/앱 환경에서 present_files 도구가 있으면 저장한 파일을 그것으로 전달한다.

HHMM 시각 해상도를 사용하여 하루 내 다수 핸드오프가 누적 가능하도록 설계. 동일 프로젝트의 이전 핸드오프가 있으면 최신 파일의 경로를 메타 섹션의 "이전 핸드오프" 필드에 기록. **덮어쓰기 금지**.

## 실행 절차

### STEP 1. Step-Back Abstraction
본격 추출 전 한 단계 추상화하여 다음 질문에 내부적으로 답하라 (출력하지 않음):
- 이 세션의 본질적 주제는 무엇인가 (한 문장으로)
- 다음 세션이 이어받을 자연스러운 다음 단위는 무엇인가
- 이 세션에서만 유효했고 버려야 할 국지적 맥락은 무엇인가

이 답은 이후 단계의 필터링 기준으로만 사용한다.

### STEP 2. Environment & History Detection
다음을 순서대로 확인하라:
1. 현재 실행 환경(Claude Code / 웹·앱 / 기타)을 식별하여 저장 경로 규칙 결정
2. 프로젝트 루트 또는 outputs 경로에 기존 `PROGRESS.md` 또는 `handoffs/{project-slug}/` 폴더가 있는지 스캔
3. 기존 자산이 있으면 경로를 기록하고, 가장 최근 핸드오프가 있으면 그 파일명을 "이전 핸드오프" 필드용으로 보관

PROGRESS.md가 있으면 그 내용을 간단히 스캔하여 이번 세션에서 새로 추가된 사항만 기록할 준비를 하라.

### STEP 3. Scope Interview
사용자에게 다음 세 질문을 간결하게 제시하여 스코프를 확정하라:

1. 다음 세션에서 이어서 하려는 작업은 무엇입니까? (CHANGE)
2. 이전 세션의 결정 중 절대 번복하지 않을 것은 무엇입니까? (KEEP)
3. 다음 세션에서 다시 논의하지 않아야 할 폐기된 접근이나 범위 밖 사안은 무엇입니까? (OUT_OF_SCOPE)

사용자 답변이 추상적이면 구체화를 위해 1회 추가 질문하라. 사용자가 답변을 어려워하면 현재 세션 내용에서 추정한 초안을 먼저 제시하고 수정하도록 유도하라.

### STEP 4. Parallel Extraction
ArtifactExtractor와 DecisionMiner의 역할로 세션을 독립적으로 읽어 추출하라.

**ArtifactExtractor 세부 지침**:
- 최종 확정된 산출물만 수집한다
- 사용자가 "이대로 가자", "확정", "좋다", "OK" 등으로 승인한 버전, 또는 세션 말미의 최종 버전을 최종으로 판정
- 원문을 그대로 보존하며, 코드블록·표·인용 형식을 유지
- 산출물이 외부 파일로만 존재하거나 크기 밸브(약 300줄·15KB)를 넘으면 경로·링크·크기·핵심 발췌만 기록하고 본 문서에 중복 복사하지 않는다
- 비밀값·개인정보가 섞여 있으면 자리표시자로 치환한다

**DecisionMiner 세부 지침**:
- 의사결정 항목마다 {결정 내용, 근거, 번복 금지 여부}를 기록
- 가드레일 제약조건을 {제약 내용, 발생 맥락} 형태로 기록
- 외부 레퍼런스(URL, 첨부파일, 인용 자료)를 {출처, 용도} 형태로 기록
- 미결 질문을 {질문, 보류 사유, 우선순위 H/M/L} 형태로 기록
- 재유혹 위험이 있는 폐기 항목을 {폐기된 접근, 폐기 사유} 형태로 기록

### STEP 5. Noise Filtering
추출 결과에서 다음 항목을 제거하라:
- 중간 버전 및 초안 (최종본만 남긴다)
- 폐기된 접근과 그 논의 과정 (단, 재유혹 위험 항목은 경계 사항으로 보존)
- 완료된 디버깅·오류수정 기록
- 사용자의 단순 감탄·확인 반응
- 재확인 목적의 반복 질의응답

제거 과정에서 "이것이 제거되면 다음 세션에서 동일한 실수를 반복할 위험이 있는가"를 자문하라. 위험이 있다면 "경계 사항" 섹션으로 이관.

### STEP 6. Document Assembly
아래 구조로 핸드오프 md 파일을 조립하라. **내용이 없는 섹션은 통째로 생략한다.**

````markdown
# 핸드오프: {프로젝트명} — {YYYY-MM-DD HH:MM}

- 프로젝트: {프로젝트명}

- 다음 세션 목표: {한 문장 요약}
````

섹션 3(확정된 산출물)의 원문은 요약·변형 없이 그대로 보존한다. 섹션 9의 "첫 지시문" 블록은 그 자체로 자기완결적이어야 하며, 선행 체크리스트는 반드시 포함한다. 섹션 9의 선행 체크리스트는 OUT_OF_SCOPE 확인을 작업 개시 전 의무 단계로 못 박는다.
